Key Technical Enhancements to Support This Flow
Durable Nonce / Advance Signed Permit:
When the user signs in Stage 2, you create a Durable Nonce Account on Devnet (system_program::create_nonce_account).
The user signs an emergency withdrawal instruction using the durable nonce as the blockhash, and the signed transaction is passed to the Kelvara backend relayer.
Because it uses a durable nonce, this signed transaction never expires due to blockhash timeouts.
Instant Backend Relayer Execution:
When the attack transaction is submitted in Stage 3, your backend monitoring script detects the state change on GGwyWv...Y98, advances the nonce, and submits the pre-signed evacuation transaction to the RPC.
Pure Browser Session State:
Store the burner wallet secret key in sessionStorage. If the user refreshes, they can pick up right where they left off; if they close the tab, the burner keypair is wiped cleanly.
